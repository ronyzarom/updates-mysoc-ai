MySoc Updates Platform

Release Notes — 1.7.0

Operator / Reseller / Customer license ownership
Version 1.7.0 August 2026 updates.mysoc.ai

Overview

Release 1.7.0 aligns the Updates Platform with the real sales flow: a SOC operator buys the mysoc platform and sells siemcore + swf to end customers — directly or via a reseller. One mysoc installation serves all of an operator's customers, and the platform now models, validates, and visualizes exactly that.

SOC operator (platform license)
├── mysoc platform node(s)
├── Customer A — direct            └─ siemcore ─ swf, swf …
└── Customer B — via reseller      └─ siemcore ─ swf …

What's New NEW

  • License ownership. Licenses now carry an operator and an optional reseller. A platform license (mysoc-cloud) defines an operator; every other license is a customer license grouped under its operator. Resellers are sales metadata — they deploy no software.
  • Smarter fleet linking. A customer's siemcore that declares the operator's mysoc as its parent now links correctly across licenses instead of being flagged as an orphan. “Orphan” now strictly means the declared parent is not enrolled anywhere.
  • Operator-grouped tree. The fleet tree (dashboard and API) is grouped operator → customer → siemcore → swf, with the operator's mysoc nodes shown as platform roots. Customers appear as soon as their license exists — even before the first instance enrolls.
  • Dashboard improvements.
    • Create License is scope-aware: Customer (siemcore + swf) or SOC Operator (mysoc platform), with an operator dropdown, optional reseller fields, and an swf product option.
    • Instances → Tree renders the operator grouping with reseller badges.
    • License detail gains an admin-only Ownership panel to classify existing licenses.
  • Documentation. New License Ownership Guide; API contract and updater guidelines updated for the ownership model.

Breaking Change API

Fleet-tree API response shape GET /api/v1/instances/tree now returns { "operators": [...] } instead of { "customers": [...] }. The bundled dashboard ships in lockstep — only external consumers of this endpoint need to adapt. Full schema in the API Contract, §5.8.

No Action Needed for Agents UNCHANGED

SiemCore & SWF teams The agent wire protocol is unchanged: heartbeats and update checks still send product_tier and parent_instance_id, and existing configurations keep working as-is. Reminder for production wiring: a customer siemcore's parent_id is the operator's mysoc instance id; each swf points at its customer's siemcore.

Upgrade Notes (Server Operators)

  1. Apply database migration 011_license_ownership (additive and idempotent).
  2. Deploy the server and dashboard together.
  3. Optionally: create the operator's platform license, then assign operator (and reseller, where applicable) on existing customer licenses via the new Ownership panel. Until then they render under Unassigned — functionally harmless.
