1  The Sales Flow, and How the Server Models It

The platform mirrors the commercial reality:

  1. MySoc sells the mysoc platform to a SOC operator.
  2. The operator sells to end customers — directly or through a reseller. Resellers add customers in the mysoc platform; they deploy no software of their own.
  3. Each customer is assigned one or more siemcore servers.
  4. The customer can install SWF (SiemCore Windows Forwarder) on Windows servers to ship Sysmon and WMI logs into their siemcore.
SOC operator  (platform license — runs one mysoc serving all its customers)
├── Customer A            — direct sale                    (customer license)
│     └── siemcore-a1     — parent = operator's mysoc
│           ├── swf-01    — Sysmon/WMI forwarder
│           └── swf-02
└── Customer B            — sold via reseller "acme-channel" (customer license)

Security note Every node covered by one license presents that license's key in X-License-Key. The key identifies the fleet; it never authorizes administration or release uploads — those require a separate admin/API key issued from the dashboard.

2  Creating Licenses in the Dashboard

Only users with the admin role can create or edit licenses (Dashboard → Licenses → Create License).

2.1  Create the operator's platform license (once per operator)

  1. Choose scope SOC Operator (mysoc platform).
  2. Enter the Operator ID (e.g. cyfox-soc) and Operator Name.
  3. Products default to mysoc-api, mysoc-frontend.
  4. Set the expiry and create. The key is issued as MYSOC-….

2.2  Create a customer license (one per customer)

  1. Choose scope Customer (siemcore + swf).
  2. Enter the Customer ID and Customer Name.
  3. Pick the SOC Operator from the dropdown. “Unassigned (set later)” is allowed, but the customer will sit in the Unassigned group of the tree until fixed.
  4. If the sale went through a channel, fill Reseller ID and Reseller Name; leave empty for a direct sale.
  5. Products default to siemcore-api, siemcore-collector, siemcore-frontend, swf.
  6. Set the expiry and create. The key is issued as SIEM-….
One key per customer Hand the customer exactly one SIEM-… key: their siemcore server(s) and every swf agent all present the same key.

2.3  Assign ownership on existing licenses

Licenses created before release 1.7.0 have no operator. On the license detail page, the Ownership card shows SOC Operator: Unassigned — click Edit, set the Operator ID (and reseller, if applicable), and save. The fleet tree regroups immediately.

3  Wiring the Agents

Each agent self-reports its tier and parent on every heartbeat and update check:

Nodeproduct_tierparent_id (config)license_key
mysocmysocomit — rootOperator's platform license
siemcoresiemcoreThe operator's mysoc instance idThe customer's license
swfswfThat customer's siemcore instance idThe same customer license

A siemcore's parent legitimately lives under a different license (the operator's). The server resolves parent links across the whole fleet — this is a normal link, not an error.

4  Reading the Fleet Tree

Dashboard → Instances → Tree view. The fleet is grouped as operator → customer → siemcore → swf:

  • Platform (mysoc) — the operator's own nodes, listed at the operator level.
  • Customer cards — one per customer license, with the masked key, node count, and a reseller badge when sold through a channel. A customer appears as soon as its license exists, even before any instance enrolls.
  • orphan badge — the node declared a parent that is not enrolled anywhere. Typical causes: the parent has not enrolled yet, or a typo in the agent's parent_id.
  • Unassigned — licenses without an operator, plus an Unlicensed / unbound bucket for instances that presented no valid license key. Cleanup work, not errors.

5  Frequently Asked Questions

Does the SWF team need to change anything for 1.7.0?
No. Config and protocol are unchanged. The wiring rule stands: swf's parent_id is the customer's siemcore; the siemcore's parent_id is the operator's mysoc instance id.

Can one customer run several siemcore servers?
Yes. They all share the customer's license key, and each declares the operator's mysoc as parent.

Can a license key upload releases?
No. Release uploads require an admin/API key issued from the dashboard; license keys only identify and validate the device fleet.

What happens if an operator is never assigned?
Everything keeps working — validation, updates, heartbeats. The license and its instances simply render in the Unassigned group of the tree.
