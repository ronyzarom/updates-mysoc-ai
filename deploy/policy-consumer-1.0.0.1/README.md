# Signed policy consumer 1.0.0.1 — local candidate only

Updates owns this privileged consumer and the companion Go `pkg/policyauth` wire codec. This is a provisioning package, not an updater self-update and not a SiemCore release. No host installation or policy authorization has occurred.

Consumer accepts the existing fixed apply/rollback wrapper calls. With no request, it delegates unchanged to recovery1.0.0.4. A signed policy request uses domain `mysoc-policy-authorization-v1\n`, canonical sorted-key ASCII JSON and the existing root-pinned Ed25519 key. Grant binds hostname, exact old policy SHA/revision, product, from/target version, target artifact checksum/signature, full source commit and lifetime <=1hour. Both archives and current runtime prerequisites are independently validated by existing recovery code. Only one forward edge is appended, copying existing mount requirements. No DB reads/copies/backups/restores are requested by the installer/authorization path; application health and configuration/image preflight remain required.

Successful policy maintenance emits only `MYSOC_POLICY_RESULT_V1` with exact request/policy hashes and status. This must run as a distinct serialized updater maintenance operation, not an ordinary product apply: it must never advance product version or report application success. The Go codec verifies the same grant bytes. Local origin admin issuance, relay forwarding and serialized Linux updater invocation are implemented; they are not deployed. Existing old updaters MUST NOT be given a pending policy-request.json.

Consumer checks signatures, duplicate/unknown fields, predecessor policy, forward version, expiration, protected runtime module checksums, pending application transactions, retained artifacts and live predecessor health. It records durable before/after policy receipts and supports interrupted-commit retry. Artifact SHA binds the exact payload; the full source commit in the grant is provenance and must be verified by the issuer against that artifact, not inferred by the consumer.

## Implemented delivery interface (not deployed)

`POST /api/v1/admin/instances/{uuid}/policy-authorizations` requires full admin authentication. Body is `{payload, previous_policy, previous_revision}`; `previous_policy` is the base64 exact observed policy bytes. The issuer validates current reported version, hostname, testing-only alpha identity and an existing signed **legacy stable/alpha** target release. Operator must independently verify full source commit and predecessor health before issuance. It never generates a grant from ordinary upload. Grants persist in the artifact store's separate `policy-authorizations` namespace, not a database migration.

A Linux updater advertises `policy_authorization_version` only after the fixed root-owned consumer is installed. The matching normal update offer can carry the signed `policy_authorization`; new relays preserve it without signing or interpreting it. Old clients do not advertise and old relays may omit the field, so origin/relay updates must precede leaf qualification. Missing grants cannot bypass the existing root whitelist.

The updater first verifies/downloads the application archive, then validates the grant independently, stages a fixed 0600 request and invokes the existing sudo apply boundary as a separate maintenance step. Its cycle mutex plus Linux process flock cover both normal and targeted work. It requires the exact root-generated request hash/result, removes the request, and only then starts normal application apply/health/report. Failure reports `kind=policy_authorization, stage=prerequisite` and never invokes application rollback. Installed product version advances only after actual application health. Interrupted requests may retry only if byte-identical and still valid; a different/expired request requires explicit reconciliation and blocks application work.

Remaining release gates: authenticated issuance against isolated real repository fixtures, full root consumer preflight with both signed native product archives, interrupted policy commit followed by normal application success/rollback, and live alpha bootstrap through the approved real provisioning channel. No backend, relay or updater version bump/publication is included in this code change.
